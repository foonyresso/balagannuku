# Архітектура

Гекс-стратегія (Settlers/Anno + герої з Dungeon Village 2). Vite + TypeScript (strict) + PixiJS, кооператив 2–8 гравців через WebRTC.

## Шари
- `src/shared/` — **контракти** (лише типи й чисті константи/функції, без залежностей): `GameState`, `Command`, `SaveFile`, мережеві повідомлення, стежки.
- `src/sim/` — детермінована симуляція `(state, commands) -> state`. Без DOM/Pixi, запускається headless для тестів.
- `src/render/` — PixiJS, лише читає стан. Три LOD (далеко/середньо/близько).
- `src/net/` — WebRTC, лобі, хост/клієнт.
- `src/ui/` — інтерфейс.

Залежності: `render`, `net`, `ui` → `shared`, `sim`; `sim` → тільки `shared`.

## Стан
Весь стан — одне дерево `GameState` (`shared/state.ts`). NPC — SoA (typed arrays, індекс = `NpcId`). Серіалізація: JSON, typed arrays → `PackedArray` (base64). ГПВЧ із seed у стані — симуляція детермінована.

## Команди
Єдиний спосіб змінити стан (`shared/commands.ts`). Клієнт → хост → валідація → застосування на тіку → `CommandResult`.

## Мережа
Хост-авторитетна. Клієнти шлють `command`, хост розсилає `events` і періодичні `snapshot` (раз на `SNAPSHOT_INTERVAL_TICKS`). Вхід: код кімнати + нікнейм + токен; при втраті токена хост призначає місто вручну з лобі. Світ живе, лише поки хост онлайн.

## Збереження
Один `.save` файл (`shared/save.ts`): `magic`, `version`, `state`. При завантаженні `migrateSave` послідовно застосовує `MIGRATIONS[N]` до `SAVE_VERSION`. Автозбереження в IndexedDB (`persist/storage.ts`, поточне + попереднє, інтервал у `persist/config.ts`) — страховка; `SaveController` (`persist/controller.ts`) робить автосейв за таймером і ручні Save/Load, меню `persist/saveMenu.ts`. Світ серіалізує `sim.serialize/deserialize`; у `SaveFile` лежить ще `speed`. Зберігає лише хост. Несумісний сейв → `SaveError` з текстом «почни нову гру». Headless-перевірка: `scripts/smoke-save.cjs`. Продовження: завантажити сейв → лобі з новим кодом кімнати → гравці повертаються за токеном.

## Стежки (емерджентні дороги)
`shared/trails.ts`. Кожен сектор має `Uint16Array` трафіку на клітинку.
- Прохід NPC: `+TRAIL_STEP_ADD`. Раз на `TRAIL_DECAY_INTERVAL` тіків: `×TRAIL_DECAY_FACTOR` (згасання — невикористані стежки заростають).
- Стадії — похідні від порогів (гістерезис 0.8): None → **витоптана** (20) → **дорога** (150) → **вимощена** (800). Пороги — баланс, змінюються без зміни формату сейва.
- У сейві зберігається лише трафік; стадію рахує sim, рендер малює тайл за стадією (на 3-й — може бути окремий об'єкт/сегмент).
- Будівля має `entrance`; якщо вхід або сусідня клітинка ≥ Road, `roadAttached = true` (кеш). Дорога дає NPC множник швидкості (`ROAD_SPEED_MULT`), прикріплена будівля — бонус у sim.
- Пошук шляху враховує вартість клітинки (вищий трафік — дешевше), тож стежки підсилюються самі.
- Мережа: зміни стадій йдуть подією `trail_stage_changed`; повний трафік — у знімку.
- Це відступ від брифу («без доріг»): носіїв по дорогах як у Settlers усе ще немає, дороги лише прискорюють і дають прикріплення.

## Продуктивність
SoA, спатіал-хеш для кліку по NPC, спрощена симуляція далеких NPC, flow fields для масових маршрутів. Симуляція незалежна від LOD.

## Зміна контрактів
Зміна форми `SerializedGameState` = підняти `SAVE_VERSION` + міграція; зміна повідомлень = підняти `NET_PROTOCOL_VERSION`. Паралельні гілки не правлять `src/shared/` без узгодження.

## Економіка (src/sim)
- `world.ts` — `SimWorld`: `GameState` + робочі дані секторів (сітка 64×64: вузли дерева/каменю, зайнятість, трафік) і NPC (фаза, шлях). Робочі дані не в сейві напряму: `serialize/deserialize` пакують трафік і залишки вузлів у `SectorState.trails/nodes`; після завантаження NPC перепланують дію.
- `step.ts` — `stepWorld`: цикл NPC (лісоруб/кар'єр: вузол → добування → склад; лісопильня: склад → переробка → склад), стежки (трафік, згасання, стадії, `roadAttached`), відростання дерев, будинки дають населення.
- `path.ts` — один A* на подорож (не на крок), вартість клітинки залежить від стадії стежки; NPC йде за готовим шляхом.
- `commands.ts` — `place_building`, `demolish_building`, `assign_worker`, `unassign_worker`; `startCity`, `staffBuilding`.
- `flow.ts` + `shared/flows.ts` — облік потоків для візуалізатора ланцюжків: `GameState.flows` (cur/last/total): вироблено/спожито/простій по будівлі та ребра `від>до:ресурс` (0 = природа).
- Обмеження етапу: NPC працюють у межах свого сектора; баланс — `sim/balance.ts`. SAVE_VERSION = 2.

## Сітка: тайли й клітинки навігації
- **Тайл** — найменша одиниця (`TILES_PER_CELL = 4` тайли на клітинку; сектор = `SECTOR_SIZE` = 256×256 тайлів): позиції NPC (дробові, рух вільний), стежки (u16 трафік на тайл), footprint будівель. **Клітинка** (`SECTOR_CELLS` = 64) — зона навігації: A* шукає шлях по ній (як і раніше, без втрат у швидкості), далі шлях спрощується за видимістю в тайлах.
- Розміри в тайлах (`sim/balance.ts`): NPC 2×2 (візуально), дерево 3×3, камінь 4×4; будівлі — `FOOTPRINT` (будинок 6×6, лісоруб/кар'єр 8×8, лісопильня 10×10, склад 12×12, ратуша 20×20). Вхід — по центру нижньої межі footprint; `BuildingState.size` лежить у сейві.
- Стежки: стадія по тайлу, ширина «пензля» `TRAIL_BRUSH_TILES` = 1 / 3 / 5 тайлів (стежка / дорога / вимощена); вартість A* бере максимальну стадію тайлів клітинки (`cellStage`).
- Вузли ресурсів зберігаються по клітинках; тайл-якір усередині клітинки — детермінований (`nodeTile`).
- Чому 4: тайл = 4 одиниці площини (дрібніше за будівлі в 1.5–5 разів), 64k тайлів/сектор = 128 КБ трафіку; бенчмарк 2000 NPC ≈ 4 мс/тік. SAVE_VERSION 3: сейви з містом старої сітки відхиляються з повідомленням, світи без міста переносяться.
